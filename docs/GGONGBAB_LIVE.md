# 꽁밥 LIVE (밥도둑 2.0 Phase 1)

소유자가 확정한 밥도둑 2.0 요구사항(2026-11-08, Q1–Q37)의 첫 단계입니다. 오늘의 꽁밥 페이지(`ggongbab.html`)에
저장, 공유, 캘린더 추가, 선택 필터를 더했습니다. 로그인, 서버 저장, 새 DB 테이블, 외부 서비스 설정은 없습니다.
2단계(로그인, 마이 밥도둑)와 3단계(식당 DB, 밥약 메이커)의 설계는 [BABDODUK_2_PLAN.md](BABDODUK_2_PLAN.md)에 있습니다.

**상태:** lab 작업 브랜치 `agent/claude/ggongbab-live`에 있습니다. lab 배포, 소유자 확인, main 반영은 아직 하지 않았습니다.

## 무엇이 바뀌나

| 기능 | 동작 | 하지 않는 것 |
|---|---|---|
| ☆ 저장 | 줄 오른쪽의 별, 또는 펼친 행사의 "저장" 버튼을 누릅니다. 저장한 꽁밥은 목록 위의 **저장한 꽁밥 N** 상자에 모입니다(접혀 있음; `#saved` 주소로 열린 채 시작). | 서버에 보내지 않습니다. 저장했다고 참석한 것으로 기록하지 않습니다. |
| 바뀐 내용 표시 | 저장한 뒤 시간이나 장소가 바뀌면 줄에 **변경됨**이 붙습니다. 펼치면 "저장할 때 …→ 지금 …"이 나오고, **확인했어요**를 누르면 표시가 사라집니다. | 공개 데이터에는 이전 상태가 없어서, 방문자가 저장할 때 본 값과만 비교합니다. |
| 지난 꽁밥 | 끝난 저장 행사는 저장 상자의 **지난 꽁밥**으로 옮겨지고, 지울 때까지 남습니다. | 끝났다고 열렸다고 하지 않습니다. |
| 목록에서 빠짐 | 아직 끝나지 않았는데 공개 목록에서 사라진 저장 행사입니다. "취소됐거나 내용이 바뀌었을 수 있어요"라고 쓰고 공지 확인을 권합니다. | **취소**라고 단정하지 않습니다. 공개 데이터에 취소 필드가 없습니다(아래 "남은 일"). |
| 공유 | 펼친 행사의 **공유** 버튼과 목록 위의 **이번 주 꽁밥 공유** 버튼입니다. 휴대폰 공유창을 열고(카카오톡을 고를 수 있음), 공유창이 없으면 링크를 복사하며, 복사도 안 되면 길게 눌러 복사할 글을 보여 줍니다. | 개인 메모나 저장 목록은 링크에 넣지 않습니다. 카카오 전용 공유 카드는 쓰지 않습니다(아래 "남은 일"). |
| 공유 링크 | `ggongbab.html?e=<행사 id>`는 그 행사를 펼친 채 그 자리로 보냅니다. 저장된 필터가 가리면 그 방문에서만 풉니다. 끝난 행사면 "끝났어요"와 날짜·제목을, 없으면 "찾지 못했어요"를 보여 줍니다. `?week=<날짜>`는 그 날짜가 든 주(월–일)만 보여 주고, **전체 일정 보기**로 풉니다. | 로그인 없이 열립니다. 형식이 틀린 값은 무시합니다. |
| 캘린더에 추가 | 펼친 행사의 **캘린더에 추가**를 누르면 **Google 캘린더** 링크와 **캘린더 파일 (.ics)** 받기가 나옵니다. 한 번에 한 행사만 추가하고, 내용은 제목, 시작·끝(UTC로 정확히 변환), 장소, 음식, 밥도둑 링크입니다. | 전체 일괄 등록이나 자동 동기화는 없습니다. 끝나는 시간이 없으면 지어내지 않고 "끝나는 시간은 공지에 없어요"라고 씁니다. 신청 마감만 있는 경품 행사에는 버튼이 없습니다. |
| 필터 | 음식 칸(기존) 아래 **날짜·대상·위치** 버튼 하나를 누르면 펼쳐집니다. **날짜**: 전체·오늘·이번 주·다음 주. **대상**: 새내기·학부생·대학원생·누구나·조건 확인 필요. **위치**: 북측(N)·동측(E)·서측(W)·장소 확인 필요. 맞는 행사가 없으면 고른 조건과 **필터 초기화**를 보여 줍니다. | 날짜·대상·위치는 저장하지 않습니다(날짜는 오늘 기준이라 다음 방문에 헷갈림). 음식 칸 저장 방식(`{when, food}`)은 그대로입니다. |
| 진행 중 | 지금 시간이 시작과 끝 사이면 **진행 중** 표시를 붙입니다. | |
| 새 기능 안내 | 페이지 제목 아래 한 줄(NEW)을 보여 주고, ×로 닫으면 다시 나오지 않습니다. 목록을 가리지 않습니다. | |

## 규칙

* **대상 필터**는 공지에 적힌 글만 봅니다(`audience.text`, 없으면 `eligibility`). 추정(`basis: inferred`)이거나
  글이 없으면 **조건 확인 필요**입니다. 새내기·신입생·학번 → 새내기와 학부생, 학부생·학사과정·재학생 → 학부생,
  대학원·석사·박사·연구자 → 대학원생. 이 셋에 안 걸리고 "누구나", "관심 있는 분" 같은 말만 있을 때만 **누구나**입니다.
  학과·인원·납부 조건은 펼친 행사의 "대상"에서 확인하라고 필터 아래에 적습니다.
* **위치 필터**는 KAIST 건물 번호의 첫 글자입니다(N 북측, E 동측, W 서측; `data/campus/buildings.json`의 94동이 모두 이 셋).
  번호가 없으면(예: "1호관") 장소 확인 필요입니다.
* **날짜**는 KST입니다. "이번 주"는 오늘부터 이번 주 일요일까지, 주는 월요일에 시작합니다(학식과 같은 기준).
* **시간 상태**: 끝(`endAt`, 없으면 시작 + 3시간, `js/ggongbab-select.js`의 `eventEnd`)이 지나면 끝난 것이고, 시작과 끝 사이면 진행 중입니다.
  이것은 시계로 계산한 상태이고, 공식 변경·취소 정보와는 다릅니다.

## 저장 형식 (localStorage)

| 키 | 값 |
|---|---|
| `babdoduk-ggongbab-saved` | `{"v":1,"items":[{"id","savedAt","seen":{"title","startAt","endAt","place"}}]}` (최대 300개, 최근 것이 앞) |
| `babdoduk-ggongbab-saved-unreadable` | 읽을 수 없던 원래 값의 사본(한 번만). 저장 상자는 "새로 시작했어요"라고 알립니다. |
| `babdoduk-notice-ggongbab-live` | `"1"`이면 새 기능 안내를 닫았다는 뜻입니다. |

* 행사 전체를 복사하지 않습니다. 화면은 늘 최신 공개 데이터를 보여 주고, `seen`은 바뀐 점을 알려 주는 데만 씁니다.
* `id`는 공개 데이터의 행사 id입니다. 여러 날 행사는 날마다 `<id>#<n>`(`F.occurrences`)이라, 그날만 저장됩니다.
  공유 링크에 `#` 없는 id가 오면 그 행사의 다가오는 첫 날을 엽니다.
* 형식이 깨졌으면 사본을 남기고 빈 목록으로 시작합니다. 이 페이지보다 새 버전(`v` > 1)은 보여 주기만 하고 다시 쓰지 않습니다.
  저장이 안 되는 브라우저(사생활 보호 모드 등)는 "이 브라우저에서는 저장할 수 없어요"라고 알립니다.
* 2단계 로그인 동기화는 이 형식을 그대로 서버로 옮길 수 있게 만들었습니다(`id` + `savedAt` + `seen`, 버전 필드).

## 코드

* `js/ggongbab-live.js` (`window.BabdodukLive`): 저장소, 변경 비교, 대상·위치·날짜 판정, 캘린더(Google 링크, RFC 5545 .ics,
  75바이트 줄 접기), 공유 링크와 공유 순서(공유창 → 복사 → 손으로 복사). 네트워크 요청이 없습니다.
* `js/ggongbab.js`: 줄의 별, 펼친 행사의 도구 줄, 저장 상자, 필터 패널, 공유 링크 처리, 안내 한 줄, 상태 알림(`.gg-toast`, `role=status`).
* `css/ggongbab.css` 끝의 "꽁밥 LIVE" 묶음, 문구는 `i18n/ko.json`·`en.json`의 `gg.live.*`.
* 홈 달력, 3D 지도, 학식, 매거진, 제보, 생성 데이터, 파이프라인, Supabase는 바꾸지 않았습니다.
