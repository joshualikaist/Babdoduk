## 2단계: 로그인 + 마이 밥도둑 (설계만)

**전제:** Supabase Auth를 처음 켭니다. Google과 Kakao 제공자 설정, 리디렉션 주소 등록, 새 표와 RLS(마이그레이션 011 이후)는 모두 승인 대상입니다.
무료 플랜 기준 MAU 5만까지 무료입니다(실행 전에 현재 요금표로 다시 확인).

| 항목 | 설계 |
|---|---|
| 로그인 | Supabase Auth의 Google, Kakao(OIDC) 제공자. 페이지 이동 방식(팝업 아님)이라 카카오톡 안 브라우저에서도 같은 흐름. Google은 카카오톡 안 브라우저(WebView)의 OAuth를 막으므로, 그때는 "기본 브라우저로 열기"를 안내합니다. 로그인은 선택이며, 방문 즉시 띄우지 않습니다. |
| Kakao 이메일 | 이메일 동의 없이도 가입되게 합니다(사용자 식별은 Supabase `auth.users.id`). 이메일로 계정을 자동 연결하지 않고, 같은 사람이 두 제공자로 들어오면 "계정 연결"을 사용자가 명시적으로 합니다(Supabase identity linking). |
| 표 | `profiles(user_id pk → auth.users, display_name, created_at)` 비공개. `saved_events(user_id, event_id, saved_at, seen jsonb, primary key(user_id, event_id))`. 3단계용 `saved_places`, `place_notes`, `place_lists(id, user_id, title, is_public, share_slug)`. |
| RLS | 기본 거부. 모든 개인 표는 `user_id = auth.uid()`인 행만 읽기·쓰기. 공개 리스트는 `is_public = true`인 리스트와 그 식당 id만 보이는 별도 view로 열고, 메모·프로필은 절대 포함하지 않습니다. 서비스 키는 브라우저에 두지 않습니다. |
| 게스트 병합 | 로그인 직후 `babdoduk-ggongbab-saved` v1을 읽어, 서버에 없는 id만 넣습니다(같은 id는 서버 값 유지, `saved_at`은 이른 쪽). 덮어쓰거나 지우지 않고, 병합한 개수를 알려 줍니다. 공용 PC를 위해 "이 브라우저의 저장 목록을 이 계정에 합칠까요?"를 한 번 묻고, 로그아웃해도 브라우저 목록은 남깁니다. |
| 탈퇴·삭제 | 본인 재인증 뒤 서버 함수(security definer, 본인만)가 개인 표 행과 `auth.users`를 지웁니다. 법정 보존 의무가 생길 데이터는 없게 설계합니다(결제·주문 없음). 브라우저 저장은 "이 브라우저 기록도 지우기" 선택지로 따로 지웁니다. |
| 화면 | 마이 밥도둑(`my.html`): 저장한 꽁밥(1단계 상자와 같은 규칙), 먹킷리스트(3단계), 계정(연결된 제공자, 로그아웃, 탈퇴). |
| 검사 | RLS 계약 테스트(다른 사용자 행 읽기·쓰기 실패), 병합 단위 테스트, 가짜 Auth로 브라우저 흐름. 실제 OAuth는 실기기에서 손으로 확인합니다. |

## 3단계: 식당 DB + 밥약 메이커 + 정산

**상태 (2026-11-08):** 소유자가 착수를 승인했습니다. lab 작업 브랜치 `agent/claude/bobyak`에 `bobyak.html`(실험실 전용)로 구현했고,
동작과 남은 일은 [BOBYAK.md](BOBYAK.md)에 있습니다. 식당 데이터는 비어 있습니다. 공공데이터 키 입력, 운영자의 식당 확인, 제보 마이그레이션 012 적용, main 반영은 아직이고 각각 승인이 필요합니다. 아래 표는 착수 전 설계입니다.

| 항목 | 설계 |
|---|---|
| 출처 | 후보: 공공데이터포털의 소상공인시장진흥공단 상가(상권) 정보(파일, API), 행정안전부 지방행정 인허가(일반·휴게음식점, 영업 상태 포함). **이용 조건, 출처 표시, 무료 호출 한도는 착수 때 원문으로 확인합니다**(지금 확인하지 않음). API가 맞지 않으면 월 1회 파일을 받는 방식으로 합니다. |
| 범위 | KAIST 교내, 어은동, 궁동. 행정동·좌표 다각형으로 자릅니다. |
| 검증 상태 | `verified`(운영자가 직접 확인), `candidate`(공공데이터만), `stale`(폐업·상호 변경 의심), `closed`. 화면에서 글자로 구분합니다. 메뉴, 가격, 영업시간은 확인된 것만 보여 주고 만들어내지 않습니다. |
| 갱신 | 정기 작업이 새 파일과 지금 DB를 비교해 신규, 폐업 의심, 상호·주소 변경 후보를 만들고, 운영자가 승인한 것만 공개 파일(`data/places/latest.json`)에 들어갑니다. 꽁밥 파이프라인과 같은 "후보 → 검토 → 공개" 구조이고, 기존 자동화는 건드리지 않습니다. |
| 식당 id | 공공데이터 관리번호를 원본 키로, 사이트 id는 그것과 무관한 안정된 값으로 둡니다. 같은 가게가 두 출처에 있으면 주소·좌표·상호로 묶고, 묶음은 운영자가 확정합니다. |
| 룰렛 | 기존 "오늘 뭐 먹지"(메뉴 뽑기)와는 다른 화면입니다. 한 번 누르면 검증된 식당 중 하나를 뽑고, 지역·음식 종류·예산은 원할 때만 고릅니다. 조건에 맞는 검증 식당이 없으면 "확인 안 된 후보도 넣을까요?"를 묻고, 동의할 때만 섞습니다. 저장한 식당만으로 뽑기도 됩니다. |
| 먹킷리스트 | 가고 싶어, 가봤어, 또 갈래와 개인 메모(비공개). 로그인 전에는 브라우저에, 로그인 후 2단계 표로 동기화합니다. 리스트 단위로만 공개 링크를 만들 수 있습니다. |
| 정산 | 1/N, 한 사람이 전부, 특정 인원 제외, 사람별 금액 조정. 원 단위로 계산하고 남는 원은 정해진 규칙(예: 앞사람부터 1원씩)으로 나눠 합계가 항상 총액과 같게 합니다. 결과는 글로 공유하고, 금액은 서버에 보내지 않습니다. 결제·송금·계좌 연결은 없습니다. |
| 지도·공유 | 네이버 지도, 카카오맵 검색 링크(상호 + 주소로 검색해 동명 가게를 피함). 식당 상세 링크는 로그인 없이 열립니다. 행사별 미리보기와 같은 이유로, 식당별 카카오 미리보기에는 서버 함수나 미리 만든 페이지가 필요합니다. |
| 제보 | 기존 제보(`tip.html`)처럼 함수로만 받고, 운영자가 확인한 것만 반영합니다. 공개 평점·리뷰는 없습니다. |

## 승인 체크리스트

1. 1단계: lab 반영 → babdoduk-lab에서 휴대폰·한영 확인 → 소유자 승인 → main.
2. 내비 이름을 "꽁밥 LIVE"로 바꿀지(공통 화면이 바뀌므로 기준 화면 승인이 필요하고, 실시간처럼 읽히지 않게 할 문구도 정해야 함).
3. Kakao Developers에 `www.babdodukms.com` 등록, OG 주소 새 도메인으로 교체, 옛 주소 리디렉션.
4. 익명 통계 도구를 쓸지(무엇을, 어떤 개인정보 없이, 비용).
5. 2단계 착수(Supabase Auth, Google·Kakao 제공자, 마이그레이션 011+).
6. 3단계 착수(공공데이터 이용 조건 확인 포함).
