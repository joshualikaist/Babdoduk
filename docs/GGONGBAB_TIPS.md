# 꽁밥 제보 게시판 (lab 전용)

소유자 결정(2026-10-31): 레이더가 놓친 오프라인 꽁밥을 방문자가 알려 주는 게시판을 만든다. 제보는 사이트에서 바로 보내고(Supabase), 소유자가 하루 한 번 확인한다. 확인하기 쉽도록 포스터나 현장 사진도 함께 받는다.
**lab 전용**입니다. `tip.html` 은 `noindex, nofollow` 이고, `vercel.json` 이 babdoduk-lab 이 아닌 모든 주소에서 404 로 답합니다. `main` 으로 옮기려면 따로 승인된 작업이 필요합니다. `main` 의 페이지는 Supabase 설정을 갖지 않습니다(AGENTS.md).

## 흐름

1. 방문자가 `tip.html` 에서 제보를 보냅니다. 브라우저는 `ggongbab_submit_tip(...)` 만 부르고, 함수가 검사한 뒤 제보를 저장하고 그 id 를 돌려줍니다.
2. 사진이 있으면 같은 id 의 폴더(`<id>/1.jpg` 등)로 비공개 버킷에 올립니다. 사진이 실패해도 제보는 접수되고, 화면이 "사진은 올라가지 않았어요"라고 알려 줍니다.
3. 운영 PC 가 새 제보(`status = 'new'`)를 텔레그램으로 소유자에게 보냅니다. 사진은 운영 PC 가 백엔드 키로 직접 내려받습니다.
4. 소유자가 ✅ 를 누르면 운영 PC 가 `ggongbab_tip_board` 에 행을 쓰고 제보를 `accepted` 로 바꿉니다. ❌ 는 `rejected` 입니다.
5. 게시판은 확인된 제보만 보여 줍니다. 다가오는 것을 가까운 날짜부터, 그다음 지난 2주를 최근 날짜부터 보여 줍니다.

3·4단계(텔레그램 확인, 게시판 쓰기, 사진 정리)는 운영 쪽 코드(`scripts/ggongbab/`)의 몫이며 이 문서의 표와 권한이 그 계약입니다.

## 표와 버킷

| 이름 | 내용 | 브라우저 |
|------|------|----------|
| `ggongbab_tips` | 제보: 행사 이름(2~80자), 장소(1~80자), 날짜, 시간(40자), 음식·경품(120자), 자세히(1000자), 링크(선택, `http(s)://`, 300자), `image_count`, `client_hash`, `status`(`new`·`accepted`·`rejected`), `notified_at`, `reviewed_at`, `dooray_post_id` | 못 봄, 못 씀 |
| `ggongbab_tip_board` | 게시판: 확인된 제보의 행사 이름, 장소, 날짜, 시간, 음식, `accepted_at`. 같은 id, 제보가 지워지면 함께 지워짐 | 읽기만 |
| `ggongbab_tip_rate` | 남용 제한: (주소+한국 날짜+비밀 소금)의 해시, 시간 창, 제보 수. 하루 지나면 지움 | 못 봄 |
| `ggongbab_tip_secret` | 해시 소금 | 못 봄 |
| 버킷 `ggongbab-tip-images` | 비공개. JPEG·PNG·WebP, 장당 5MB | 올리기만(아래 조건) |

- 게시판에는 자세히·링크·사진·보낸 사람에 관한 값이 없습니다. 원본 포스터는 공개 사이트에 다시 싣지 않습니다.
- `image_count` 는 0 으로 둡니다. 사진 수는 운영 PC 가 버킷에서 셉니다.
- 백엔드 키(`service_role`)는 제보를 읽고 상태를 바꾸며, 게시판과 버킷을 모두 다룹니다.

## 브라우저가 할 수 있는 것

- `ggongbab_submit_tip(p_title, p_place, p_event_date, p_time_text, p_food, p_details, p_link, p_hp)` → 새 제보 id(uuid).
  - 앞뒤 공백을 지운 뒤 길이와 날짜(한국 날짜로 어제부터 60일 뒤까지), 링크를 검사합니다. 어긋나면 `TIP_INVALID` 입니다.
  - 같은 주소에서 한 시간에 6번째 제보, 또는 24시간 동안 전체 60건을 넘으면 `TIP_RATE_LIMITED` 입니다.
  - `p_hp` 는 사람에게 보이지 않는 칸(허니팟)입니다. 값이 있으면 봇으로 보고 아무것도 저장하지 않은 채 임의의 id 를 돌려줍니다. 봇은 차이를 알 수 없습니다.
- 사진 올리기(`storage.objects` INSERT 만): 경로가 `<제보 id>/<1|2|3>.<jpg|png|webp>` 이고, 그 제보가 `new` 이며 15분 안에 보낸 것이고, 폴더에 사진이 3장 미만일 때만 됩니다. 덮어쓰기, 읽기, 목록, 지우기, 공개 주소는 모두 안 됩니다. 검사는 `ggongbab_tip_upload_allowed(name)` 이 합니다.
- `ggongbab_tip_board` 읽기.

## 화면 (`tip.html`, `css/tip.css`, `js/ggongbab-tips.js`)

- 머리: "모르는 꽁밥, 알려 주세요", 확인은 하루 한 번 · 확인된 제보만 공개 · 사진·세부 내용은 비공개, 제보 예시 티켓(장식).
- 순서 세 칸(제보 → 운영자 확인 → 게시판 공개), 받는 제보와 빼 줄 것(개인정보, 대학원생 전용, 온라인 참여만 하는 추첨, 판매·할인).
- 제보 칸: 행사 이름, 장소, 날짜, 시간, 음식·경품, 자세히(글자 수), 링크, 사진(최대 3장, 미리보기와 빼기 버튼). 2000px 보다 크거나 5MB 를 넘는 사진은 브라우저에서 긴 변 2000px JPEG 로 줄여 올립니다.
- 칸마다 이유를 적고(`aria-invalid`), 첫 칸으로 초점을 옮깁니다. 상태는 `role="status"` 로 읽힙니다. 고치면 표시가 바로 사라집니다.
- 공개 설정(`js/ggongbab-public-config.js`)이 비었거나 클라이언트를 불러오지 못하면 제보 칸이 닫히고 "지금은 제보를 받을 수 없어요", 게시판은 "게시판을 불러오지 못했어요"라고 말합니다. 이때 페이지는 아무 요청도 하지 않습니다.
- Supabase 클라이언트는 공개 피드와 같은 고정 버전(`@supabase/supabase-js@2.116.0`, integrity 포함)입니다.
- 진입: `lab.html` 의 버튼, `lab-ggongbab.html` 의 "꽁밥 제보하기", 실험 페이지 더보기의 "꽁밥 제보". 공개 페이지(`ggongbab.html` 등)는 lab 전용 페이지에 링크하지 않습니다(`tests/test_deploy_config.py`). 승격할 때 `ggongbab.html` 진입점을 함께 넣습니다.

## 운영 규칙

- 소유자가 하루 한 번 확인합니다. 확인 전 제보는 공개하지 않습니다(불확실한 정보는 비공개 검토, Stage A 자동 공개 금지 유지).
- 운영 PC 는 확인(또는 거절) 14일 뒤 그 제보의 사진을 지웁니다. 제보의 글과 판단은 남깁니다.

## 적용 (소유자, 한 번)

1. Supabase 대시보드 → SQL Editor 에서 `supabase/migrations/007_ggongbab_tips.sql` 내용을 붙여 넣고 실행합니다(006 다음). 버킷과 사진 정책도 이 파일이 만듭니다.
2. 확인: Storage 에 `ggongbab-tip-images` 가 **Private** 로 보이고, Table Editor 에 `ggongbab_tips`·`ggongbab_tip_board` 가 RLS 켜짐으로 보이면 됩니다.
3. 적용 전에도 페이지는 안전합니다. 함수가 없으면 제보가 "보내지 못했어요"로 끝나고, 게시판은 "불러오지 못했어요"라고 말합니다.

## 시험

- `tests/test_ggongbab_tips.py`: SQL 의 권한(브라우저는 게시판 읽기, 함수 실행, 조건부 사진 올리기뿐), 저장 열, 검사·제한 코드, 버킷과 정책, 페이지 스크립트가 쓰는 경로(함수·게시판·업로드만, 같은 고정 클라이언트).
- `scripts/check_site_ui.py` `tip_board`: 가짜 클라이언트와 고정 시계로 게시판 순서(오늘 표시, 지난 2주), 잘못된 제보, 사진 거절·3장 제한·빼기·큰 사진 축소, 제한 초과·서버 실패 시 칸 유지, 제보 id 아래 사진 올리기, 사진 실패 안내, 영어, 빈 설정에서 요청 없음.
- 정적 검사는 모두 빈 설정으로 돌아 어떤 페이지도 DB 에 닿지 않습니다.
