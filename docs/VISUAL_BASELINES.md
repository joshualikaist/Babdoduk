# 공통 chrome 시각 기준 이미지

내비게이션과 푸터는 모든 페이지에서 같아야 합니다. `python scripts/check_site_ui.py` 는 구조·목적지·계산된 스타일을 검사하는 **사이트 가디언**과 함께, 아래 스크린샷을 승인된 기준 이미지(`tests/visual/chrome/`)와 비교합니다.

| 캡처 | 범위 |
|------|------|
| `nav` | 고정 상단 내비 전체 |
| `footer` | 푸터 전체 |
| `footer-context` | 푸터 바로 위 180px + 푸터 전체. 한 페이지에서만 푸터가 따로 떨어진 판처럼 보이는 문제(2026-09)를 잡기 위한 캡처 |

- 페이지: `index`, `ggongbab`, `choose`, `mukbang`, `event`, `food`, `history`. 한국어·영어, 1440×900·390×844.
- 결정성: 오프라인(외부 폰트·서비스 차단), 브라우저 시계 고정(`2026-09-28T10:00+09:00`), 생성 데이터 대신 고정 fixture, 애니메이션·전환 끔, 2% 필름 그레인 오버레이 숨김.
- 비교: 크기가 같아야 하고, 채널 차이가 24/255 를 넘는 픽셀이 0.2% 이하여야 통과합니다. 실패하면 `.local/visual-diff/` 에 실제 이미지와 차이 이미지가 남습니다.
- 기준 이미지는 이 저장소의 Windows 작업 환경(설치된 Chrome, 시스템 대체 폰트)에서 만든 것입니다. 다른 OS·Chrome 버전에서는 차이가 날 수 있으며, 그때도 아래 절차를 따릅니다.

## 기준 이미지를 바꾸는 조건 (자동 승인 없음)

새 스크린샷으로 기준을 덮어쓰면 회귀를 숨길 수 있습니다. 기준 이미지는 다음이 **모두** 있을 때만 바꿉니다.

1. 의도한 UI 변경이다(작업 브랜치와 커밋이 있다).
2. 그 변경이 babdoduk-lab 에 배포되었다.
3. 소유자가 lab 화면을 보고 검토했다.
4. 소유자가 명시적으로 승인했다.

```powershell
python scripts/check_site_ui.py --update-chrome-baselines --approval "<누가, 언제, 어디서 승인했는지>"
```

- `--approval` 없이는 기준을 쓰지 않습니다. 메모는 `tests/visual/chrome/BASELINES.json` 에 남습니다.
- 검사가 실패했을 때 기준을 다시 만들어 “통과”시키지 않습니다. 먼저 `.local/visual-diff/` 의 차이 이미지로 원인을 확인합니다.
- 소유자 승인 전의 기준은 메모에 `PENDING` 으로 적고, 승인되면 같은 이미지로 메모만 갱신하거나 승인 후 다시 만듭니다.
